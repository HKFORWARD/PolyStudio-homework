# 媒体到播客的自动二创

## ⚠️ 铁律（贯穿全流程，绝不破例）

1. **必须 7 步全部完成**才能向用户交付——任何中间产出（前置检查结果、Omni 返回、脚本、音色样本、单段音频、拼接音频）**都不是最终答案**。
2. **严禁**把脚本、音色样本、单段音频或拼接音频作为最终回复展示给用户。
3. Step N 完成后**立即开始 Step N+1**——不停顿、不汇报中间产出、不询问用户。
4. 仅当 Step 7 输出最终 `.mp3` 路径时，才能向用户报告"播客已生成"——这是**唯一**允许"停下并交付"的时刻。
5. 如果在 messages 历史中看到自己刚写完脚本，**绝不能**误以为任务完成——**必须**继续调 `qwen_voice_design_tool` 进入 Step 4。

## 适用场景

**触发条件（必须同时满足）**：
- ✅ 用户已上传视频（mp4/mov/avi/mkv/webm）或音频（mp3/wav/m4a）文件
- ✅ 用户表达了"把这个内容做成播客"、"二创"、"提炼播客"或类似意图

**不适用场景（避免误触发）**：
- ❌ 用户只给主题文字、没上传任何媒体 → 应使用 `podcast-creator`
- ❌ 用户上传的是图片 → 不在本 Skill 处理范围
- ❌ 用户想做视频拼接 / 字幕 / 长视频处理 → 不在本 Skill 处理范围

## 核心工作流程

严格按以下 7 步顺序执行，全程无人值守，**所有歧义按"默认值汇总"采用固定值**。

### 第 1 步 · 前置检查（门禁拦截）

**目标**
作为 gatekeeper，只让符合要求的文件进入后续昂贵的工具调用链；不符合的直接终止，避免烧无谓 token。

**不调用任何工具**——LLM 仅依据 messages 历史中的 `media_path` 字符串和文件元数据完成判断。

**检查清单（全部通过才进 step 2）**：
| # | 检查项 | 预期 |
|---|---|---|
| 1 | `media_path` 是否存在 | 非空字符串 |
| 2 | 后缀在白名单内 | `.mp4, .m4v, .mov, .avi, .mkv, .webm, .mp3, .m4a, .wav` |
| 3 | 文件大小 | ≤ 25 MB |

**默认值（无人值守关键）**：
- 文件大小阈值固定为 25 MB（不询问用户）
- 类型识别以**扩展名为准**，不询问用户

**强制核对（不允许跳过）**：
在调用任何工具之前，**必须**先用一段文字 self-check 上述 3 项，**并在回复中明确写出 "前置检查通过：路径=X，类型=Y，大小=Z MB"** 再继续。如果 messages 历史中没有显式 file size 信息，则**保守按"未知"处理**——直接进 Step 2，但要在心里准备好 28MB API 上限的兜底。

**通过 → 完成条件**：
- 已写出"前置检查通过"的明确文字
- **立即**进入第 2 步，不停顿、不询问

**未通过 → 失败兜底（不重试、不询问，直接终止）**：
- 后缀不在白名单 → "仅支持 mp4/mov/avi/mkv/webm 视频或 mp3/wav/m4a 音频格式"
- 大小超阈值 → "文件超 25 MB，请压缩到 20 MB 以下后重传"
- `media_path` 为空 → "未检测到上传文件，请先上传视频或音频"

### 第 2 步 · 多模态理解（提取媒体核心内容）

**目标**
把用户上传的视频或音频转成可供后续脚本生成使用的文字描述。
**不做任何中间格式转换**——qwen_omni_understand 直接吃视频/音频，无需先抽取音频或转录。

**调用工具**：`qwen_omni_understand_tool`

**参数**：
| 参数 | 取值 | 说明 |
|---|---|---|
| `media_path` | 从 messages 历史拿到的上传路径 | 通常 `/storage/videos/upload_xxx.mp4` 或 `/storage/audios/upload_xxx.mp3` |
| `question` | 固定为："请详细描述这段媒体的核心内容、关键信息、人物、场景，输出可用于撰写播客脚本的素材摘要" | 不向用户征询替代提法 |
| `media_type` | 留空 | 工具按扩展名自动识别 |
| `output_audio` | `false` | 这一步只要文字 |
| `voice` | 不传 | output_audio=false 时无效 |

**默认值（无人值守关键）**：
- 上述 `question` 措辞**直接复用**，不询问用户偏好
- `output_audio=false`，不向用户确认是否需要语音回答

**完成条件**：
- 工具返回的 JSON 字符串可解析，且 `text_response` 字段长度 ≥ 100 字
- 把 `text_response` 直接作为下一步「写脚本」的输入摘要

**失败兜底（fail fast，不重试、不询问）**：
- 含 "exceeds the maximum allowed" → 文件超 28MB 限制，**终止流程**，告知用户："文件过大，请压缩到 20 MB 以下后重传"
- 含 "未配置 DASHSCOPE_API_KEY" → **终止流程**，告知"系统未配置百炼 API"
- 其他错误 → **终止流程**，原始错误透传
- **严禁调用第二次** `qwen_omni_understand` 重试——根因不变只会烧重复 token

### 第 3 步 · LLM 写脚本（不调工具）

**目标**
把 step 2 的 `text_response` 转写为可直接喂给 TTS 的播客脚本。

**不调用任何工具**——LLM 内部能力完成。

**输出格式硬规定**：
- **形式**：单人独白
- **长度**：500 字左右（450-550 字区间）
- **拆段**：5-7 段，段间用空行（双换行 `\n\n`）分隔
- **每段**：80-100 字，保持完整语义

**默认值（无人值守关键）**：
- 主持人风格：默认"亲切自然的单人主持人"，不询问用户偏好
- 语气基调：默认"轻松专业"，不询问用户偏好
- 字数 / 段数 / 形式 全部按上述固定，不询问用户

**禁止行为（防越位）**：
- ❌ 禁止脚本开头写"好的，这是为您准备的脚本..." 等元评论
- ❌ 禁止任何舞台提示（如 `(笑)`、`(停顿 2 秒)`、`[音效]`）
- ❌ 禁止 Markdown 格式（`**加粗**`、`*斜体*`、`#` 标题）
- ❌ 禁止 emoji
- ❌ 禁止任何询问 / 确认句（如"您觉得这个开头怎么样？"）
- ❌ 禁止引用视频时间戳（如 `(00:15) 此时...`）

**完成条件**：
- 脚本字数在 450-550 区间
- 用 `\n\n` 拆出 5-7 个段落
- 每段是可独立朗读的完整句子

**⚠️ 关键提醒（防止误以为任务完成）**：
- 这份脚本**仅作为 Step 4-5 的内部素材**——**严禁**向用户展示这份脚本完整内容。
- **严禁**在写完脚本后停下来等待用户反馈、确认或评价。
- 完成本步后**必须立即调用 `qwen_voice_design_tool`** 进入 Step 4，不允许有任何"汇报""总结""征询"等过渡话术。
- 如果你刚写完脚本，正在考虑"是不是该把脚本告诉用户"——**停止这个念头，立即调 qwen_voice_design_tool**。

### 第 4 步 · 设计音色样本（qwen_voice_design × 1）

**目标**
生成一段"音色样本" `reference_audio.wav`，**不作为播客成品**——仅供后续 voice_cloning 当作音色参考。

**调用工具**：`qwen_voice_design_tool`

**参数**：
| 参数 | 取值 | 说明 |
|---|---|---|
| `voice_description` | `"亲切自然的女主持人音色，温暖友好，语速适中、清晰流畅"` | 固定写死，不询问用户 |
| `text` | `"大家好，欢迎收听今天的播客节目，今天我们将聊一个有意思的话题。"` | 固定通用试听文本，与播客内容无关，丢弃即可 |

**默认值（无人值守关键）**：
- 音色描述固定为亲切女主持人，**严禁向用户征询性别 / 年龄 / 风格**
- 试听文本固定为上述一句话，**严禁让用户决定试听内容**

**完成条件**：
- 工具返回 `audio_url` 字段（路径形如 `/storage/audios/voice_design_xxx.wav`）
- 把这个路径在内存中标记为 `REFERENCE_AUDIO`，供 step 5 的 N 次 voice_cloning 复用
- 这段音频本身**不进入最终播客**

**失败兜底（fail fast）**：
- 工具返回 `Error:` → 终止流程，告知用户"音色合成失败：{原始错误}"
- **严禁重试**——即便失败也不再调一次 voice_design

### 第 5 步 · 逐段克隆音频（qwen_voice_cloning × N）

**目标**
按脚本拆出的 N 段（5-7 段），逐段调用 voice_cloning，使用 step 4 的音色样本作为参考，生成 N 个统一音色的 .wav 文件。

**调用工具**：`qwen_voice_cloning_tool`（调用 N 次）

**遍历指令（强约束防漏段）**：
- 把 step 3 的脚本按 `\n\n` 拆分得到段列表 `segments[]`，长度 N
- **必须**对 `segments[]` 中**每一段**依次调用 voice_cloning
- **不允许**跳过任意段，**不允许**合并多段为一次调用，**不允许**用 LLM 自己合成代替工具调用

**每次调用的参数**：
| 参数 | 取值 |
|---|---|
| `reference_audio` | step 4 完成态保存的 `REFERENCE_AUDIO` 路径 |
| `text` | 当前段的完整文本（保持原始标点和换行不修改） |

**默认值（无人值守关键）**：
- 段落顺序 = 脚本中出现顺序，**不调整、不优化、不询问用户**
- reference_audio 始终复用 step 4 的同一个样本，**全 N 段保持音色一致**

**完成条件**：
- N 段全部成功 → 收集 N 个 audio_url 路径，按段序排列成 `SEGMENTS[]` 数组
- 进入 step 6

**失败兜底（每段独立处理）**：
- 单段返回 `Error:` → **立即用同样参数重试 1 次**（业内 70%+ 瞬时抖动可挡住）
- 二次失败 → **终止整个流程**，告知用户"第 X 段克隆失败，请稍后重试"
- **严禁第三次重试**——避免无限循环烧 token

### 第 6 步 · 拼接所有段（concatenate_audio）

**目标**
把 step 5 产出的 N 段 .wav 按段序拼接，段间留 1.2 秒静音，得到一段完整的对话音频。

**调用工具**：`concatenate_audio_tool`

**参数**：
| 参数 | 取值 |
|---|---|
| `audio_files` | step 5 完成态的 `SEGMENTS[]` 数组（按段序排列） |
| `silence_duration` | `1200` （毫秒） |

**默认值（无人值守关键）**：
- 静音时长固定 1200ms（标准播客节奏），**不询问用户**
- 段顺序严格按 step 5 输出顺序，**不重排、不删段**

**完成条件**：
- 工具返回拼接后的 `.wav` 路径
- 在内存中标记为 `CONCATENATED_AUDIO`，供 step 7 混音用

**失败兜底**：
- 工具返回 `Error:` → 终止流程，告知用户"音频拼接失败：{原始错误}"
- **不重试**——pydub 拼接失败几乎都是文件路径或文件本身问题，重试无意义

### 第 7 步 · 添加 BGM 并输出成品（select_background_music + mix_audio_with_bgm）

**目标**
为 step 6 的对话音频自动匹配 BGM、混音输出最终成品 .mp3。

#### 子步 7a · 自动选 BGM
**调用工具**：`select_background_music_tool`

- 输入：脚本内容（或 step 2 的 `text_response` 摘要）传给工具
- 工具内部用 LLM 自动从 `storage/bgm/` 按主题匹配
- 不询问用户偏好

**BGM 库为空时的兜底（优雅降级）**：
- 工具返回空或错误 → **跳过混音**，直接把 `CONCATENATED_AUDIO` 复制为 .mp3 作为成品交付
- 不报错终止

#### 子步 7b · 混音（仅当 7a 成功时）
**调用工具**：`mix_audio_with_bgm_tool`

| 参数 | 取值 |
|---|---|
| `dialogue_audio` | step 6 的 `CONCATENATED_AUDIO` |
| `bgm_audio` | 7a 选中的 BGM 路径 |
| `intro_duration` | `3000` 毫秒（开场原声时长） |
| `bgm_volume_after_intro` | `0.05` （5% 背景音量） |

**默认值（无人值守关键）**：
- 混音方案固定为 README 标准（开场 3s 原声 + 渐弱到 5%），**不询问用户**
- BGM 选择由 LLM 自动决策，**不让用户挑文件**

**完成条件**：
- 输出最终 `.mp3` 路径，告知用户"播客已生成：{path}"
- 流程结束 ✨

**失败兜底**：
- 7b 失败 → 走 7a 的兜底（直接交付无 BGM 版本）
- 7a + 7b 都失败 → 终止流程，告知用户原始错误

## 禁止行为汇总

**全流程通用**：
- ❌ 严禁中途询问用户任何参数（音色、字数、形式、BGM 等）
- ❌ 严禁等待用户确认中间产出
- ❌ 严禁展示中间结果（如脚本、音色样本）等待反馈
- ❌ 严禁单段失败重试超过 1 次（防止无限循环烧 token）
- ❌ 严禁绕过任一步骤直接合成（破坏可调试性）

**脚本（Step 3）**：
- ❌ 元评论："好的，这是为您准备的脚本..."
- ❌ 舞台提示：`(笑)`、`(停顿 2 秒)`、`[音效]`
- ❌ Markdown 格式：`**加粗**`、`*斜体*`、`#` 标题
- ❌ Emoji
- ❌ 询问/确认句："您觉得这个开头怎么样？"
- ❌ 视频时间戳引用：`(00:15) 此时...`

**克隆（Step 5）**：
- ❌ 修改 `reference_audio` 路径（必须全 N 段保持同一个）
- ❌ 调整段顺序 / 删除段 / 合并段

## 失败兜底汇总

| 步骤 | 失败情形 | 处理策略 |
|---|---|---|
| Step 1 | `media_path` 为空 | 终止，告知"未检测到上传文件" |
| Step 1 | 后缀不在白名单 | 终止，告知支持格式列表 |
| Step 1 | 大小 > 25 MB | 终止，告知"请压缩到 20 MB 以下后重传" |
| Step 2 | API 错误 `exceeds the maximum allowed` | 终止（重试也无效，根因是文件大小） |
| Step 2 | API 错误 `未配置 DASHSCOPE_API_KEY` | 终止，告知联系管理员 |
| Step 2 | 其它错误 | 终止，原始错误透传给用户 |
| Step 4 | `voice_design` 失败 | 终止，**不重试** |
| Step 5 | 单段克隆失败 | **同参数重试 1 次** |
| Step 5 | 二次仍失败 | 终止整个流程，告知"第 X 段克隆失败" |
| Step 6 | 拼接失败 | 终止，原始错误透传 |
| Step 7 | BGM 库为空 / 选择失败 | **优雅降级**：跳过混音，直接交付无 BGM 版本 |
| Step 7 | 混音失败 | 同上，降级为无 BGM 版本 |

**贯穿原则**：fail fast + 不无意义重试 + 关键步骤优雅降级。
